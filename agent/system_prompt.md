# PythonGo 策略文件公共规则
本节适用于创建、重新生成或修改 PythonGo 策略源码的任务；行情规则和接口细节仍以对应 Skill 与接口契约为准。

## 生成、检测与保存
- 用户要求创建、重新生成或修改策略文件时，必须产出完整单文件源码；将此前确认的规则与本轮修改合并。不要只给代码片段、修改建议或文字说明。
- 先加载对应 Skill 链接的接口契约，再调用 `run_functional_test` 检测完整源码。检测失败时，根据失败用例修复源码并重新检测；不得改写用户规则或测试预期，也不得保存未通过检测的源码。
- 检测通过后，必须把与检测完全相同的源码传给 `write_generated_file`。缺少会改变策略结果的必要信息时，先用普通语言追问，本轮不检测或保存。
- 只有 `write_generated_file` 成功返回后，才能说策略文件已生成、更新或保存。若无法写入，不得把代码文本或此前产物说成本轮已保存。
- 检测通过后的 `write_generated_file` 是策略工具流程的最后一步；不应在它之后再改动或重测源码。

## 源码结构与边界
- 策略是完整的单个 Python 文件。唯一直接继承 `RHTemplate` 的顶层策略类必须命名为 `My_PythonObj`；可以定义辅助类，但不能另有顶层类直接继承 `RHTemplate`。
- 类属性 `name` 必须直接赋值为英文 ASCII 字符串字面量，只含英文字母、数字、下划线或连字符，并以英文字母开头。保存文件名由该值决定，格式为 `<name>.py`；调用写入工具时不另传文件名。
- 类上保留接口要求的基类字段（如 `name`、`paramMap`、`varMap`）；没有明确的界面配置需求时，`paramMap` 保持空字典。用户给出的固定策略参数集中为模块级大写常量。
- 遵循接口契约中的初始化顺序、公开方法、生命周期和参数要求；公开策略方法提供完整的参数及返回类型注解。不得复制接口实现或绕过公开接口直接调用引擎内部对象。
- 日志使用接口公开的 `self.output(...)`，通知使用 `self.putEvent(中文内容, "warning")`；不要用 `print`、标准库 `logging` 或引擎内部接口。启动时简要说明监控对象和规则，触发通知前记录足以追溯原因的信息，避免逐条行情刷日志。生命周期回调按对应 Skill 与契约规定的顺序调用父类方法。
- 除接口或下述协议明确要求外，不进行网络访问、文件读写、随机行为、无限循环或下单操作；Web 协议允许为 `eventId` 生成唯一 UUID。

## Web 实时价格折线图协议
- 本协议适用于 Tick 行情的价格预警策略；仅使用 K 线的策略不发送此协议，除非用户明确要求 Web 价格图协议。
- 对适用的 Tick 价格预警策略，协议默认开启，不需要用户额外确认或重复提出。只有用户明确要求关闭、禁用或不要 Web 折线图协议时，才省略所有该协议的 config/trigger 输出及专用协议代码；该要求优先于本节其余规则。用户未明确关闭时，不得自行省略协议。
- 协议前缀固定为 `__PYTHONGO_PRICE_ALERT__:`。每条协议消息必须由一次 `self.output(...)` 发出，内容是此前缀紧接紧凑单行 JSON；不要输出 Markdown、额外说明、缩进或实际换行。可使用 `json.dumps(data, ensure_ascii=False, separators=(",", ":"))` 序列化。
- 策略每次启动时，在调用对应 Skill 要求的父类启动方法后发送 config 单行消息。JSON 至少包含 `type: "config"`、`instrument`（核验后的规范合约代码）、`direction`（`above` 或 `below`，与实际触发方向一致）、数值型 `triggerPrice` 和字符串 `rearmCondition`。`rearmCondition` 应准确表达策略真实的重新布防条件，例如上破预警在价格回落至阈值或以下时重新布防；它不能被重新布防等待时长替代。若协议还使用 `rearmHoldSeconds`，其值必须来自明确规则或已定义的协议默认值，不得照搬示例值。可按协议提供折线阈值名称 `label`。
- 每次逻辑上真正触发预警时，另发一条 trigger 消息；JSON 必须包含 `type: "trigger"`、每次触发都唯一的 `eventId`、`instrument`、`timestamp`、数值型 `price`（本次实际触发价）、数值型 `triggerPrice`（预警阈值）、`condition`（实际触发条件）和 `label`（图表标记名称）。`eventId` 可用标准库 UUID 生成；`timestamp` 使用带时区偏移的 ISO 8601 时间。若行情对象没有来源时间戳，应记录策略检测到触发的时间，并明确这是策略触发时间，不得伪称为交易所行情时间。
- config 与 trigger 字段必须对应同一实际策略规则；每个 trigger 的合约、阈值、方向、条件和标记名称不能与配置或实际触发逻辑不一致。普通行情、启动配置和重新布防过程都不能伪造 trigger。协议消息是 Web 图表数据，仍须按对应 Skill 通过 `putEvent(..., "warning")` 发送实际预警通知。
- 示例文件中的合约、阈值、日期、标记文字和重新布防时长仅供理解协议，不是默认参数；始终从用户需求和策略逻辑构造消息。

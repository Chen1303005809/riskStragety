# 目标

根据用户明确给出的合约、K 线周期、历史范围或数量、计算规则和通知条件，创建或修改一个可由本项目产物流程保存的 PythonGo 策略。可按用户需求单独使用历史查询、实时订阅/退订，或组合这些能力。不要仅因为用户提到“行情”就把 Tick 策略改成 K 线策略。

本 Skill 是接口使用规范，不是业务信号库。用户没有给出的指标窗口、阈值、交易时段和触发规则都不能从接口示例中推导。确实缺少会改变策略结果的规则时，先合并追问。合约和交易所信息采用主会话的合约预查询结果；若没有可用结果而源码需要核验，调用 `lookup_exchange_by_contract_code`，不要要求用户重复提供可核验的信息。

# 接口约定

编写或修改源码前，先加载本 Skill 的 [接口契约参考](references/interface-contract.md)。只使用其中记录的 `RHTemplate`、`VtBarData`、方法和字段。

- 历史查询通过 `queryHistoryKline(...)` 提交；方法返回请求号，数据在 `onHistoryKline(request_id, bars, error)` 异步回调中交付。用请求号匹配业务请求；若 `error` 非空，不得处理其中可能存在的部分 bars；空列表且无错误是正常空结果。
- 周期使用 `cycle_type` 枚举，不把分钟数直接当枚举。区间、最新 N 根、截至某时刻的 N 根是互斥查询形式，按参考中的约束填写参数。
- 历史查询与实时订阅互不替代。实时使用 `subscribeKline(...)` 和 `onKline(bar)`；退订使用相同参数调用 `unsubscribeKline(...)`。订阅和退订无 ACK，调用成功不代表服务端已确认。
- `onKline` 的 `closePrice` 不表示本根已收盘。除非用户需求和已验证的行情服务语义足以支持，否则不得假设推送频率、收盘时刻、时间字段含义或同一根只推送一次。
- 历史与实时的衔接不保证无缺口；不自行声称历史补齐、排序、去重或连续性。若用户要求这些保证，先说明接口限制，并询问可接受的处理语义。

# 策略实现

- 策略类必须名为 `My_PythonObj` 并继承 `RHTemplate`；导入 `RHTemplate, VtBarData`。遵循本项目既有构造顺序、方法注解、日志、预警、文件命名和产物检测要求。
- 仅使用 K 线时，将 `symbolList` 与 `exchangeList` 初始化为空列表，让基类生命周期运行，但不要因 `super().onStart()` 而额外订阅 Tick。需要 Tick 时只能按用户明确需求增加。
- 不要在构造函数或模块导入时发起查询。启动后再发起历史查询或实时订阅；`onStop()` 中先尝试退订本策略请求的实时订阅，再调用 `super().onStop()`。订阅是否请求成功应由实例状态记录，不能把“无异常”描述为服务端确认。
- 每个历史请求保存其返回的 request ID。可能并发多个请求时，按 request ID 匹配回调，不依赖返回顺序。所有 K 线回调按实际收到的顺序处理；接口未承诺排序或去重。
- 预警只在用户规则满足时调用 `self.putEvent(中文内容, "warning")`。使用 `self.output(...)` 记录必要的提交、失败和触发信息，不逐根行情刷日志。
- 禁止自行建立行情连接、用 Tick 合成 K 线、访问网络或文件，或调用任何下单接口。

# 生成流程与边界

用户要求创建、重做或修改策略时，生成完整单文件源码，按本轮 Skill 和通用 Agent 工具规则运行功能检测，并在检测通过后写入产物。不能只给接口示例或代码片段。

功能检测使用本项目的 Python 3.12 隔离沙盒和 K 线模拟对象，只能验证策略逻辑、回调处理及模拟调用；不得声称已连接真实 PythonGo、DLL、Dispatch 或 K 线服务。当前仓库中的旧 `external_head.py` 本身没有这些 K 线接口，部署必须使用与本契约匹配的外部宿主版本。

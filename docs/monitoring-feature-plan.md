# 真实账号与会话监控功能计划

本文记录第一版占位参数之后的实施路线。当前 `account_id` 和 `conversation_id` 只做请求校验；服务仍把请求按固定 `default` 账户处理，不保存会话，也没有监控查询接口。

## 目标与约定

- 不增加注册流程。第一次合法聊天请求创建账号记录；`account_id` 去除首尾空白后按大小写敏感的字符串区分账号。
- `conversation_id` 是全局唯一 UUID。同一账号重复使用同一 UUID 表示继续该会话；新 UUID 创建新会话。会话首次创建后绑定账号，其他账号携带该 UUID 请求时返回 404，不转移会话，也不泄露其归属。
- 账号 ID 只用于数据归属，不是身份凭证。现有共享 Bearer API Key 仍负责认证，持有该 Key 的调用方可以查看所有账号的监控信息。对外开放前，若要让账号彼此不可见，需要另行增加身份认证与授权。
- 使用 Python 标准库 SQLite 保存账号、会话、消息和生成文件元数据，默认数据库位置为 `data/monitoring.sqlite3`，并允许通过 `APP_DATA_DIR` 调整。继续把生成源码存为 `artifacts/<artifact_id>.py`；数据库保存文件归属和会话索引。数据库使用版本迁移，数据目录加入 Git 忽略规则。
- 服务端保存的消息是模型上下文和监控展示的唯一历史来源。启用持久化时，同时从聊天请求 Schema 和前端请求体中移除 `history`；服务端按 `conversation_id` 读取历史，避免客户端与数据库各自维护一份记录。

## 数据与请求流程

- 建立 `accounts`、`conversations`、`messages`、`artifacts` 四类记录。会话以 `conversation_id` 为主键并绑定不可变的 `account_id`，保存标题（取首条用户消息）、创建与更新时间、状态；消息按会话内序号保存角色、内容、时间和完成状态；文件记录保存 artifact ID、文件名、账号、会话和创建时间。
- 聊天请求只携带账号 ID、会话 ID、本轮消息和模型参数。服务端验证并读取会话历史，在事务中保存本轮用户消息，再调用 Agent；完成后保存助手回复、失败/中断状态和生成文件关联。
- Agent 的文件写入上下文接收 `conversation_id`，新文件元数据同时关联账号和会话。源码仍通过现有文件存储适配器读写；SQLite 记录负责列表、归属校验和监控查询。若数据库索引写入失败，清理本次刚写入的文件，避免留下无法查询的记录。
- 下载仍按 artifact ID 读取源码，同时核对请求 `account_id` 与数据库中的归属；不存在或账号不匹配统一返回 404，避免泄露文件是否存在。
- 对现存 JSON 元数据执行一次性导入迁移。没有会话 ID 的旧文件归入对应账号的“未关联会话文件”列表，不伪造对话历史；原始源码文件不因迁移删除。

## API 与前端阶段

1. **持久化层**：新增 SQLite 存储适配器、数据库版本迁移和并发事务处理；为 Agent 文件创建接口传入会话 ID；继续使用现有 Bearer Key。
2. **聊天写入与历史读取**：聊天路由按账号/会话恢复历史并记录用户消息、助手回复、失败状态和产物关联；从请求 Schema 与前端请求体中移除 `history`，同步更新所有 API 调用方。
3. **监控读取接口**：新增 `GET /api/monitor/accounts`（分页账号汇总）、`GET /api/monitor/accounts/{account_id}/conversations`（会话摘要和文件数）、`GET /api/monitor/accounts/{account_id}/conversations/{conversation_id}`（按时间顺序返回消息与文件详情）。所有接口沿用 API Key 认证。
4. **监控前端接线**：把现有空壳替换为账号列表、会话列表、消息时间线与会话文件区；补上加载、错误、空结果和分页状态。选择会话后可预览文件并通过带账号 ID 的下载接口下载。聊天页支持恢复选中的会话和新建会话；监控读取可手动刷新，并在页面可见时每 15 秒刷新一次。

## 验收标准

- 新账号首条聊天后创建账号和会话记录；服务重启后账号、会话、消息及文件清单仍可查看，续聊时 Agent 收到该会话历史。
- 同账号同会话 ID 会续接原会话；不同账号或不同会话 ID 的消息和文件列表互相隔离；其他账号重用已有会话 ID 时返回 404。重复/并发请求不会覆盖消息顺序或把文件关联到错误会话。
- 账号列表、会话列表和会话详情分页结果稳定；空库显示空状态；监控接口错误时显示可恢复的错误提示。
- 只有归属账号的下载请求成功；跨账号下载返回 404。会话详情中列出的文件均能预览和下载。
- 迁移可重复执行而不重复插入；旧文件保留在原位置，并可在未关联会话区域下载。

## 分阶段交付建议

- **阶段 A：存储和迁移**，先合并表结构、存储适配器、事务与旧元数据导入。
- **阶段 B：聊天闭环**，实现服务端历史恢复、消息记录、文件关联和归属下载校验。
- **阶段 C：监控 API 与 UI**，接通账号/会话浏览、详情、文件操作、分页和刷新。
- **阶段 D：上线验收**，备份当前 `artifacts/`，在副本上验证迁移与恢复；通过后部署，保留回滚所需的数据库备份和旧 API 调用方式过渡期。
